# Travel Application · Agile Retrospective

A process case study about translating user needs into workable requirements, responding to changing priorities, and keeping development aligned through clear communication. Written from an assigned Scrum Master perspective in a simulated travel application project.

**Read the [retrospective (PDF)](docs/agile-retrospective.pdf)** · [Editable Word version](docs/agile-retrospective.docx)

## What this demonstrates

| Scenario | Decision or lesson |
|---|---|
| Travel offerings shift toward wellness retreats | Revisit priorities and break the revision into manageable increments |
| Profile preferences leave behavior unspecified | Clarify toggles, reset behavior, and saving before treating the feature as complete |
| Developers and testers need the same understanding | Ask precise questions and agree on acceptance criteria rather than guessing |

The report discusses Scrum responsibilities, user stories, backlogs, communication, and the strengths and limitations of an iterative approach. Jira is discussed as a possible supporting tool; it was not used in the exercise.

## My contribution

I evaluated the supplied scenario and wrote the retrospective, connecting the changes in requirements to how work should be organized and reviewed. My emphasis was on keeping the process useful. A backlog should make priorities visible, acceptance criteria should make the work testable, and communication should resolve specific uncertainty.

The deliverable is a written retrospective of the simulated project.

## What I would carry forward

Stakeholders describe intended behavior in everyday terms. User stories keep that purpose visible, while acceptance criteria and edge cases make the work testable. I would retain ordered backlogs, manageable increments, clear completion criteria, and a regular cadence of planning, review, and reflection.

Being a useful team member means producing understandable work, asking precise questions, making blockers visible, and adapting to shared priorities. Reliability, openness, and responsibility matter throughout the process.
